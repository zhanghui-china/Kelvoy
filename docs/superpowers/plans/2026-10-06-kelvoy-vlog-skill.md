# Kelvoy Vlog Skill 实施计划

**Goal:** 在仓库内交付依赖已有部署实例的旅行 Vlog 生产技能，复用已有素材，保留三个人工审核点。

**Architecture:** `skills/kelvoy-vlog` 为唯一技能源，`.agents/skills` 相对链接供发现。Agent 通过已有 Web API 操作，服务继续负责队列、模型、存储和 FFmpeg。

**Tech Stack:** Markdown、Agent Skills YAML 元数据、现有 Cookie 会话与 HTTP API。首版无客户端、MCP 或脚本新增。

## 已确认需求

用户在 2026-10-06 选择：仓库内独立技能子目录、旅行 Vlog 生产用途、已有部署实例作为基线、复用已有素材。用户批准 proposed_plan 后明确要求实施。

- 新建一期、按作品 ID 续跑、脚本／关键帧／片段审核协作、指定镜头返工、重新合成与下载。
- 角色／目的地／模板必须来自现有可用资料，多个匹配由用户选择；缺资料转现有页面。
- 新期默认逐镜、9:16、约 30 秒；镜数、时长遵循 pacing_version，旧期不迁移。
- 用户“制作”指令已授权建期；三个审核点仍需针对当时内容的决定。
- 写入使用 row_version，遇冲突重新读取与对比；未知写结果先查询，不盲目重发。
- 不整合部署补丁、不修改服务或数据模型、不增加素材建设、批量与平台发布。
- 不固化生产地址／身份／凭据。预览不足时交现有审片页，不代选或代审。

## 验收方法

格式运行 skill-creator 的 quick_validate.py；链接检查解析 Markdown 相对目标与符号链接；行为验收由独立评估者读取技能后对给定服务状态输出 API 动作序列和停止点，不以关键词匹配代替操作推演。

行为场景包括素材歧义、泛化自动指令、选图／审片不完整、冲突使旧候选失效、建期响应丢失、返工超时但已运行、失败镜手工重试、关闭配乐重合成、HTTP 200 HTML 假成片。模拟与真实验收分别记录。

本次实施与验收结果见 [验收记录](../specs/2026-10-06-kelvoy-vlog-skill-validation.md)。真实验证依赖可达服务和人工决定，缺条件时保留待办，不能宣称已全链路验收。回退仅删除新增技能、链接和文档入口，不涉及生产数据。
