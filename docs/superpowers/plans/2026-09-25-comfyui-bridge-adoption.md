# ComfyUI 桥接能力接入计划

> 状态：执行中。2026-09-25 已完成 Spark 技术样片、ADR 和推理层接口适配；正式素材评审、Worker 逐镜闭环和整期验收待完成。本文保留原定验收门槛，不把技术样片视为质量结论。

**目标：**利用同事新增的 ComfyUI 工作流打通 Kelvoy 的 9:16 地标关键帧与 3–5 秒图生视频，保留现有的 Worker、推理接口、状态机和审片流程。

**依据：**[PRD v0.2](../../AI旅行Vlog生产工作台_PRD_v0.2.md) FR-03/04/06/07/09 与 M0–M2；`comfyui-bridge/AI_USAGE_GUIDE.md`、图像与视频参数指南；`spike/m0/eval/结论.md`。PRD 是产品约束，新指南是候选实现与待验证的参数建议。

## 1. 吸收范围

| 级别 | 桥接器能力 | Kelvoy 用途和条件 |
| --- | --- | --- |
| 现在验证并接入 | Qwen-Image 2.1 单图/双图参考编辑工作流；必要时文生图 | 角色参考图与真实地标参考图条件生成关键帧。地标镜必须有实景参考；先证实“保真且能按指令加入角色”，再定主工作流。 |
| 现在验证并接入 | MiniMax-H3 `image2video` | 选中关键帧作为首帧，输出 9:16、3–5 秒片段。 |
| 学习其机制并适配 | 工作流 JSON、上传、ComfyUI `/prompt`、WebSocket 完成通知、`/history` 与 `/view` 取回 | 通过 `services/inference` 的现有协议封装；保留模型参数、版本、seed、耗时、参考图哈希和错误原因。 |
| 只当实验起点 | 图像 1.0/1.5/2.0 MP、视频最短边 480/704/768、参考视频 0.4/0.9 MP | 新文档的推荐值不是 Kelvoy 在 Spark 上的验收值；用同一批样片比较画质、耗时、失败率。 |
| 验证后决定 | 单/多图 `ref2video`、更多图融合 | 若首帧视频跨镜角色漂移，或双图编辑无法同时保留角色与地标，再评测；不预接全部工作流。 |
| 暂不进入 MVP | 数字人、视频编辑、3/4/9 图全量接口、ACE-STEP 音乐生成 | PRD 没有口播数字人或任意视频编辑；配乐要求来自授权曲库，生成音乐不能直接代替曲库。 |

## 2. 关键差异与架构选择

- 桥接器默认 16:9 或 3:4、15 秒视频；Kelvoy 固定 9:16、3–5 秒。必须在请求中显式指定并用真实输出检查尺寸、时长和首帧，不依赖默认值。
- 桥接器默认等待 600 秒，Kelvoy 当前推理客户端/PRD 是 300 秒；此前 MiniMax-H3 的 5 秒横版样片耗时 347–603 秒。先测优化工作流是否能达标，再决定本地生成、国内 API 溢出或提交 PRD 的时限变更，不能简单把客户端超时调大。
- 桥接器返回图片/视频二进制，Kelvoy 推理接口返回路径、模型、版本、seed、耗时。媒体必须落在 `projects/<episode_id>/...`，元数据从推理层返回给 Worker，SQLite 中的期/镜状态仍是真源。
- 桥接服务默认监听 `0.0.0.0:6000`、500 MB 上传、同步等待结果；若用于试验，仅绑定 `127.0.0.1`，不经公网暴露。上线前为输入、超时、取消、并发、幂等与磁盘清理定边界。
- 工作流是可复用资产，但 `comfyui_api_service.py` 达 1347 行，不直接并入现有 FastAPI 路由。先作为内部试验服务核对工作流；生产路径由 `services/inference` 保持唯一对 Worker 的协议入口。是否长期保留桥接进程，在一镜实测和 ADR 中确定。

## 3. 分阶段任务与验收

### P0：工作流与环境核验（M0，先于接入代码）

1. 在 Spark 上核对 ComfyUI 自定义节点、模型文件、工作流 JSON 引用、可用 GPU、端口归属及服务启动方式；不要覆盖队友正在运行的 ComfyUI。
2. 准备一组可复测输入：同一角色正面/侧面/全身参考图，至少一处目的地的实拍地标图，固定 prompt、seed 和预期尺寸。
3. 分别试 Qwen 单图/双图编辑与 MiniMax-H3 首帧视频：9:16，视频 3、5 秒，至少比较快速/推荐两档分辨率。记录上传、排队、推理、取回的分段时间、显存、失败和输出文件元信息。
4. 人工逐镜记录角色脸型/发型/服装、地标必须保真特征、动作与物理合理性。复测是否能同时做到地标保真和加入角色；不能只凭文档声称质量已达标。

**通过门槛：**至少一条“角色 + 实拍地标 → 9:16 关键帧 → 3–5 秒竖版视频”链路稳定复现，产物、参数和耗时留档；若 5 分钟超时反复触发，先作本地/API 路线决策。

### P1：定义接入边界（M1）

1. 写 ADR，确定试验桥接器是临时 sidecar，还是将所需的 ComfyUI 调用能力拆入 `services/inference`；明确 Worker 仍只调用 `/image`、`/video`，Web 不直连模型服务。
2. 对照 `services/inference/src/inference/schemas.py` 与 `packages/engine/src/providers/inference-types.ts`，定义请求中的参考图 key、9:16、候选数、时长和参数 preset；响应要含路径、模型、工作流版本/哈希、seed、耗时，错误区分输入错误、模型错误、超时和取回失败。若改领域 schema，同一提交更新 PRD §6。
3. 定义固定文件 key、重试的幂等键、超时取消、排队阈值与磁盘副本处理。模型服务不得把任意客户端路径当作可读文件路径。

**通过门槛：**接口样例、错误表、状态流和 ADR 经团队确认；用本地假 ComfyUI 响应可完成协议测试，不依赖 GPU。

### P2：先通一镜，再通一场景（M1）

1. 实现图像与视频推理路由：`services/inference/src/inference/routers/image.py`、`video.py`；调用已选工作流，归一化输出与错误。
2. 实现 `packages/engine/src/providers/local-image.ts`、`local-video.ts`，以及 `packages/engine/src/stages/assets.ts`、`keyframe.ts`、`video.ts` 的最小闭环。关键帧数量来自真实保存的期配置；地标镜无参考图直接阻断。
3. 在 `apps/worker/src/queue/consumer.ts` 的任务执行中完成单镜状态和模型记录写回；失败只重跑目标镜，保留已 approved 镜。补本地重试与国内 API 溢出，不把服务端 501 当作可无限重试错误。
4. 先做 1 镜，再做 3–5 镜场景；确认候选进入审片台、选中关键帧后片段可播放、拒片可重生成。

**通过门槛：**一场景走完脚本审核、关键帧审核、视频审核；数据库记录能复现每次生成，队列重试不会重复或覆盖已批准素材。

### P3：整期验证与成本校准（M0/M1/M2）

1. 录入首批目的地真实参考图，做同一角色跨镜与跨期人工一致性评审；把网格模式策划稿单独实现，它不是桥接器现成能力。
2. 用 24–30 镜真实期测关键帧候选到达 ≤30 分钟、全片 ≤2 小时、API 费用及 GPU 分钟；根据实测回填 `packages/engine/src/rules/credits.ts`，让 `credits_used` 取真实记录。
3. 检查 ffmpeg 合成所需音频/LUT/片头片尾文件、1080×1920 30fps、卡拍、AI 标识和元数据；做一条可下载、可分享成片。
4. 最后跑无锡三期的同角色 Demo 与三个审核点现场演练；若指标不达标，记录是模型质量、速度、队列还是成本问题，并在本地/API 配比上决策。

**通过门槛：**PRD §10 的比赛 Demo 可由未参与开发的人完整走通；成本报告与真实调用相符，样片和评审记录可追溯。

## 4. 实施顺序和停止点

执行顺序为 **P0 → P1 → P2 → P3**。P0 是选型门槛：若新工作流无法在真实参考图上同时满足地标保真、角色一致性、9:16 与时间预算，停止把它接进主链，改测其他模型或国内 API。P1 不提前接入全部桥接接口；P2 不先铺满 30 镜；P3 不用空数据或假图宣称 Demo 已完成。
