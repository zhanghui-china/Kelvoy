# 永久删除作品

`DELETE /api/episodes/:id` 无需请求体，登录用户只能删除自己的作品。草稿、失败、已完成和生成中的作品均可删除。事务成功返回 HTTP 200：

```json
{"ok":true,"cleanup_status":"pending","refunded_credits":11}
```

`cleanup_status` 为 `pending` 或 `done`，`refunded_credits` 为本次退回的预留积分。未登录返回 401 `unauthorized`；不存在、其他账号及其他账号已删除的作品统一返回 404 `not_found`。同账号重复请求返回成功、本次退款为 0，不重复创建记录。分享、文件下载、详情和后续修改立即返回 404，已有下载或已缓存在浏览器的文件无法撤回。

## 事务与执行取消

store 在同一个 SQLite writer 事务中验证归属、保存消费摘要、取消 held／pending／processing 任务并清除执行租约、退回作品全部 reserved 积分动作，最后删除作品。已结算消费与积分流水保留。删除与成功回调由事务提交顺序决定：成功先提交保留消费；删除先提交则旧租约、预留、任务入队和发布均被拒绝。领域状态枚举不增加“已删除”。

新增内部 `episode_deletions` 审计表，保存账号、删除时间、必要用量摘要、清理状态、重试次数、重试时间、清理 revision 与安全错误码。它不是回收站，没有恢复接口。用量统计包含已删除作品，标注“已删除”且不提供详情链接。`task_executions` 持久化每次执行 token 及租约；启动迁移 `episode_deletions_v1` 回填旧处理中任务，重复打开数据库可安全执行。退出确认移除执行记录；清理完成后移除任务提示词、结果、错误和指令，仅留审计字段。

Worker 每秒检查取消，正常续租仍为 30 秒。AbortController 传递到脚本／H3 改写、模型 HTTP 和 FFmpeg；推理服务沿用只取消本 prompt ID 的机制，不全局 interrupt。执行的所有写入 finally 完成后才确认退出。

## 文件清理

Worker 启动及每分钟读取到期 pending 记录，等待所有未退出执行的租约过期或退出确认，再删除 `projects/<episode_id>`。仅处理明确的删除记录；不扫描历史孤立目录。根目录须为真实目录，拒绝符号链接祖先；目录内符号链接只删除链接，不跟随目标。角色、目的地、共享图、音乐、LUT、推理临时目录及其他作品不删除。

清理失败记录 `filesystem_cleanup_failed`，保持 pending，指数退避且不超过一小时，不保存原始文件错误。模型产物、缓存元数据、H3 提示词和合成发布均有持久化删除检查。已过期执行恢复文件操作时，删除检查或最终退出确认会将已完成清理重新标记 pending，每次迟到检测增加持久化 cleanup_revision；清理完成提交须与扫描时 revision 一致，避免文件删除与数据库提交之间留下迟到目录／文件。

生产备份遵循现有保留策略。回退代码保留新增审计表及防止同 ID 再建的数据库触发器，不恢复已删除作品。旧 Worker 不具备清理和取消能力，回退期间暂停 Worker，按审计记录处理未完成清理后再恢复兼容版本。
