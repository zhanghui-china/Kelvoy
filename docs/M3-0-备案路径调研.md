# M3-0 · 备案路径与主体调研

> **这是桌面调研初稿，不是可以直接拍板执行的结论。** 上线前必须找专业人士（律师 / 代办机构）核实，尤其是算法备案 / 大模型备案这块变动快、地方执行口径可能不一致，网信办各省分支的实际尺度和公开条文经常有出入。本文只负责把"要查哪几件事、条文怎么写的"理清楚，不负责"确定能不能这么做"。

对应 issue #24（M3-0），依据 PRD §8、§11。目的地是回答 PRD §11 里悬着的两条开放问题：备案路径 + 支付与备案主体。

## 结论速览

| 问题 | 初步结论 | 确定性 |
| --- | --- | --- |
| ICP 备案能不能用个体户 | 能，个体户可以做 ICP **备案** | 较高 |
| Kelvoy 是否只需要 ICP 备案 | **不是**——Kelvoy 收费卖积分包，属于"经营性互联网信息服务"，备案之外大概率还需要 **ICP 经营许可证（EDI证）** | 中，需律师确认边界怎么划 |

## 1. ICP 备案路径与所需材料

**流程**：域名 + 服务器接入商（阿里云/腾讯云等）代提交 → 接入商初审 1-2 个工作日 → 提交管局 → 短信核验 → 管局审核，通常 15-20 个工作日出结果[^1]。

**企业主体材料**：营业执照副本（最新年检版，加盖公章）、法人身份证正反面、经办人身份证 + 授权委托书（非法人办理时）、法人手持身份证照片、企业座机、法人实名手机号、企业邮箱[^1]。

**个体户/个人主体材料**：备案人身份证正反面、手机号、邮箱，部分地区要求个人承诺书[^1][^2]。个体工商户备案时按"单位"名义提交，材料接近企业但用个体户营业执照[^2]。

**关键区分点——非经营性 vs 经营性**：

> 国家对经营性互联网信息服务实行许可制度；对非经营性互联网信息服务实行备案制度。[^2]

Kelvoy 卖积分包收费，属于经营性服务。**只做 ICP 备案是不够的**——经营性网站在完成 ICP 备案后，还需要另外申请 **ICP 经营许可证（又叫 EDI 证）**[^2][^3]。这条是本次调研最关键的发现，直接影响下面第 4 节的主体选择。

## 2. 算法备案 / 大模型备案怎么走，责任主体是谁

两部相关法规，容易混着说，分开写：

**《生成式人工智能服务管理暂行办法》**（2023-08-15 施行）：适用于"利用生成式人工智能技术向中华人民共和国境内公众提供生成文本、图片、音频、视频等内容的服务"[^4]。Kelvoy 用开源图像/视频模型自部署生成内容，形态上落在这个办法的适用范围内——**自己部署开源模型，不代表可以不管这条**，办法管的是"提供服务"这个行为，不是"是否自研模型"。

**触发算法备案的条件**：办法要求"具有舆论属性或社会动员能力"的生成式 AI 服务才需要按《互联网信息服务算法推荐管理规定》做算法备案 + 安全评估[^4][^5]。这个判断标准本身比较模糊——聊天机器人、社交类应用通常被认定有舆论属性；Kelvoy 是"生成一段旅行 vlog 供用户下载/分享"，属性上更接近内容生成工具，风险相对低，**但 FR-12 的公开分享链接功能（成片可以生成一个任何人都能看的公开页面）可能被视为具备一定的对外传播/社会动员能力**，这条边界怎么划，需要律师给出判断，本文不下结论。

**责任主体**：办法把"提供者"定义为"利用生成式人工智能技术提供生成式人工智能服务的组织、个人"[^4]——Kelvoy 自己部署模型、自己对外提供服务，责任主体就是运营 Kelvoy 的这个公司/个体户本身，不能推给上游开源模型作者，这条 PRD §8 已经写对了。

**如果需要备案，流程大致是**：属地网信办材料审核 + 技术测试 → 属地初审通过后上报中央网信办 → 中央网信办材料复审 + 技术评审 → 下发备案号[^6][^7]。这个流程通常需要数周到数月，是 issue #24 标题"备案周期以周计"的来源。

## 3. 真人参考图政策对备案/审查的影响——需要单独说明，风险比预想的高

PRD §3/§4 允许用户上传真人照片作为角色参考图，责任归用户。查完《互联网信息服务深度合成管理规定》（2023-01-10 施行）后，这条设计触发了两个具体的合规义务，**不是"责任归用户"一句话能免掉的**：

1. **人脸生成/编辑类服务需要对使用者做真实身份信息核验**（即实名认证）[^8]——Kelvoy 现在的注册登录（#18，M2-2）只有用户名密码，**没有实名认证环节**，这是一个具体的产品缺口，不是纯法务问题。
2. **如果编辑的人脸不是用户本人**（比如用户上传朋友、网上找的照片做角色），深度合成服务提供者必须告知用户"须依法告知被编辑的个人并取得其单独同意"[^8]——这意味着 Kelvoy 的用户协议（M3-4，#36）里，"你上传的必须是你本人或已取得肖像权人同意的照片"这条不能只是一句免责声明，从产品设计角度可能需要一个显式的确认勾选项，且平台对"用户是否真的取得同意"这件事本身也有一定的审慎义务，不是完全甩给用户就没事。
3. 深度合成生成的内容同样需要按标识办法加标识（见第 4 节），这条 Kelvoy 已经在做。

**这条本身就值得单独立一条产品待办**（不在本次调研范围内落地，只标记出来）：M2-2 的注册流程后续可能需要补实名认证，M3-4 的用户协议需要补"肖像权单独同意"条款和对应的产品交互。

## 4. 内容标识——顺手核实的第五点

PRD §8 已经写了"《人工智能生成合成内容标识办法》（2025 年 9 月起施行）"，这次核实了具体条文，细节比 PRD 现在写的更具体：

- **显式标识**：在内容起始/末尾/中间位置加文字或图形提示，或在交互界面显著位置提示[^9]——Kelvoy 现在的设计"右下角半透明文字'AI 生成 · 虚构角色 · 真实目的地'"符合这个要求的字面意思。
- **隐式标识**：必须在文件元数据里加入生成合成内容属性信息、服务提供者名称/编码、内容编号——这是**强制要求**，不是"鼓励"；办法原文说"鼓励"的是数字水印这类更强的隐式标识形式，元数据本身是必须的[^9]。Kelvoy 现在的设计写了"元数据字段"，方向对，具体要不要包含"内容编号"这个字段，实现的时候要对着办法原文再核一遍字段清单，这次没有细到字段级别。

这条不是本次调研的主线，但顺手核实后发现 PRD 的表述基本站得住，只需要在真正实现 M1-13（合成阶段真实 ffmpeg 参数，#28）时把元数据字段对着办法原文抠一遍。

## 5. 支付主体：个体户 vs 新设公司

**支付牌照层面，两者差异不大**：微信支付、支付宝的商户号申请，个体户和企业都可以办理，都需要营业执照（个体户的营业执照也算数），费率上小微商户/个体户在部分类目可能拿到更低费率（0.38%-0.6% vs 企业档 0.6%-1%）[^10]，不构成决定性差异。

**真正决定性的是第 1 节发现的 ICP 经营许可证（EDI证）**：

> 具备独立法人资格的企业可以办理 ICP 许可证，个人和个体户不具备独立法人资格，无法办理。[^3]

Kelvoy 是收费产品（积分包购买），大概率需要 EDI 证才算完整合规——**这条如果成立，个体户路径直接走不通，只能新设公司（有限责任公司）**。

**周期/成本粗略对比**（未核实，仅供决策参考，不是报价）：
- 个体户注册：材料简单，通常几个工作日到两周，成本低（数百元级）。
- 有限责任公司注册：材料略多（公司章程、股东信息等），通常 1-2 周，成本略高于个体户但也不算大（几百到几千元，视代办服务而定）。
- 两条路径注册本身的周期差异不大，**真正的周期差异在后续 EDI 证申请上**——EDI 证审批通常比 ICP 备案更慢、材料要求更高（往往涉及网络安全等级保护测评等前置条件），这条没有查到具体周期数字，需要专业人士给出。

**初步建议：新设公司**，不是因为规模化预期或税务优化这类通常理由，而是因为 EDI 证这一条硬约束——如果律师核实后确认 Kelvoy 这个业务形态确实需要 EDI 证，个体户从一开始就不是可选项。**这条建议依赖"Kelvoy 确实需要 EDI 证"这个前提**，如果律师核实后认为不需要（比如按某种豁免情形），个体户仍然是更轻量的选项，值得重新评估。

## 待专业人士核实的清单

- [ ] Kelvoy 这个业务形态是否真的需要 ICP 经营许可证（EDI证），还是有豁免路径
- [ ] 分享链接（FR-12）这个公开传播功能，会不会让 Kelvoy 被认定为"具有社会动员能力"，从而触发算法备案
- [ ] 真人参考图这条设计，除了本文列出的实名认证 + 单独同意，是否还有其它《深度合成规定》条款没覆盖到
- [ ] 个体户注册 → 后续想升级成公司主体，ICP 备案/支付商户号需不需要重新走一遍（主体变更成本）
- [ ] 无锡本地是否有针对文旅/AI 内容行业的地方性政策差异（本文只查了国家层面法规）
