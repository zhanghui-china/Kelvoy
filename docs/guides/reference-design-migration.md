# 全站对齐版本的数据迁移与发布

## 旧数据兼容

- SQLite 启动时补 `tasks.generation_id` 和租约列，创建积分账户、动作、流水和价格表；已有用户初始可用积分为 0，历史 GPU 记录保留。已有积分流水后只做兼容迁移，不能拿旧备份覆盖新库。
- 旧期缺少 `candidate_count`、画幅和剪辑字段时分别按 2、9:16、`beat_aligned` 读取；普通查看和下载不转换。旧网格期仅可查看和下载已有文件。
- 旧逐镜期在片段审核或成片页显式选择转换：保留全部片段，把每镜改成 1 秒且清空旧起点，回到片段审核；全部再次确认后才进入合成设置。转换期间旧成片和原分享链接不提供视频；新成片成功后按原分享开关恢复。
- `final` 元数据只在合成成功后写入；旧文件仍用 `final/<期号>.mp4` 兼容读取。新合成采用递增版本号并经 ffprobe 验证。任何失败都不把未验证文件标为交付。
- `seed-catalog` 幂等导入官方角色、目的地、六个模板与共用音乐、LUT、片头片尾。已有官方角色快照保留；旧 `warm_natural` LUT 名称在 Worker 解析到 `lut/warm_film.cube`。

## DGX 发布次序

1. 核对当前提交、用户 systemd 服务、数据库和任务状态。等待旧任务处理完毕；保留 `infra/dgx` 在服务器上的服务文件与本地修改。
2. 使用 SQLite 在线备份接口生成带时间戳的数据库备份，并记录文件校验值。保留 `projects/` 现有素材；不要清理旧成片。
3. 更新代码和依赖，执行 `seed-catalog`；让新服务首次打开数据库完成列迁移。检查 `credit_actions`、`credit_ledger` 及 `tasks` 仍与备份前数量一致。
4. 重启现有 `kelvoy-web`、`kelvoy-worker`、`kelvoy-inference` 用户服务，检查三者 active、`/api/health` 和公网入口。给单独的演示账号通过 CLI 发放测试额度；普通账号维持 0。
5. 真实完成一条 9:16 和一条 16:9 流程：创建、脚本审核、候选选择、30 帧选段、字幕与转场合成、分享。通过 ffprobe 核对每镜 30 帧、最终尺寸/时长/帧率以及片头偏移；再验证失败重试与积分流水。

如果发布后发现兼容问题，优先停写并修复当前数据库。已发生积分交易后，不回滚到丢失流水的旧库。
