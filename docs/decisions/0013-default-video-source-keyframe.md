# ADR-0013：新建作品界面默认改回关键帧，服务端缺省保持直出

状态：已采纳并实现于分支 `feat/default-keyframe-ui`（2026-10-11），未发布；实施任务见 `docs/superpowers/plans/2026-10-11-default-video-source-keyframe-tasks.md`

## 背景

PRD 原始设想的流程是：脚本、参考图、每镜关键帧（N 个候选）、审核 2 选图、图生视频、审核 3、合成。2026-09-27 提交 `aa901f7` 把新项目的默认 `video_source` 改成 `references`（人物与场景直出视频），跳过关键帧与审核 2，PRD 同时加了「2026-09 人物与场景直出视频」一节覆盖旧描述。

用户反馈「关键帧选择界面没有了」，并要求改回最初设想。

核对现状（2026-10-11）：

- 关键帧路径代码完整且有真实历史：Spark 上关键帧任务已完成 175 条；缺少 `video_source` 字段的旧作品走的就是这条路径。
- 线上现有 `references` 作品：GX10 8 条、Spark 4 条。
- `skills/kelvoy-vlog` 与 [ADR-0008](0008-agent-production-skill.md) 明确依赖「`video_source=references` 默认路径（无关键帧审核）」。服务端 `apps/web/src/server/routes/episodes.ts` 的缺省值（创建与估价两处）若改成 `keyframe`，不传该字段的代理与 CLI 调用会静默改变行为与计费。

## 决策

1. Web 界面（新建页）默认 `video_source` 回到 `keyframe`；直出（`references`）保留为高级设置里的可选项。
2. 服务端缺省值不改：请求不传 `video_source` 时仍为 `references`。API 契约不变。
3. 不删除 `references` 分支；已有 `references` 作品不迁移，缺少字段的旧作品照旧按关键帧流程运行。
4. 新建页草稿里已保存 `videoSource` 的保持原值，未保存的取新默认，不做迁移。
5. 详情页对 `references` 作品显示一行提示，说明本期无关键帧审核，解决「界面没了」的困惑。
6. `CLAUDE.md` 首段「三个人工审核点」不改：默认路径回到关键帧后，该表述对用户看到的默认流程重新成立；直出作品只有两个审核点，已由 PRD 直出一节与详情页提示说明，不需要在项目总览里分叉。

## 理由

- 用户可见的「默认」回到原设想，同时 API 的外部契约不动。
- 成本口径：直出不产生图片积分；默认走关键帧后新作品会多出图片积分（每镜候选数取用户设置 `default_candidates`，缺省 3），预估积分由现有 `estimateCost` 随 `video_source` 给出，无需改动，但需让用户知晓默认花费上升。
- 保护 `skills/kelvoy-vlog` 等外部调用方，避免静默改变行为与计费。
- 旧作品不迁移，沿用 PRD 已有的「旧项目不自动转换」承诺。

## 后果

- 前端有默认值、文案与详情页提示的改动；服务端、engine、worker、store 不改。
- Web 默认与 API 缺省不一致，必须在 API 文档与 `skills/kelvoy-vlog/references/kelvoy-api.md` 中写明；依赖直出路径的调用方应显式传 `video_source`。
- 默认花费上升，需要在发布说明与用户沟通中提示。
- 发布只涉及前端与文档，无数据库迁移、无素材变更。
- 回退：把前端默认值改回 `references` 即可，无数据层影响。

## 被否决的方案

- **服务端缺省一并改为 `keyframe`**：全局一致，但会让不传该字段的代理与 CLI 调用静默改变行为与计费，需要同时改 skill、通知使用方并重新评估计费口径，改动面大且无用户收益。若将来确需统一，另开 ADR，并同步更新 `skills/kelvoy-vlog` 与相关集成测试。
- **彻底删除直出**：线上已有 12 条 `references` 作品需要继续可用；skill 依赖该路径；直出对纯空镜、低成本场景仍有价值。删除只会造成数据与调用方破坏。
- **保持直出为默认，仅在界面加入口**：不满足用户要求回到最初设想的诉求，「看不到选图界面」的问题仍在。
- **自动把旧直出作品转换为关键帧**：违背 PRD「旧项目不自动转换」，且已生成的视频素材无对应候选图。
