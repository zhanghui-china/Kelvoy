# ADR-0015 角色穿搭：每套自带参考图，每期选一套

状态：已采纳（2026-10-12）

## 背景

`default_outfit` 与 `brief.outfit_override` 只被存储、展示和内容审核，从未进入任何模型输入：
脚本提示词不含角色，关键帧只吃 `persona.refs[0]` + 地标图。因此角色穿什么，完全取决于第 1 张
参考图里的衣服，用户写再多文字也不会改变成片。用户需要同一角色在不同场景/季节穿不同的衣服。

## 决定

1. 穿搭放进 Persona 文档：`outfits?: PersonaOutfit[]`（`outfit_id/name/desc/seasons/refs`），
   至多 6 套，每套 1–3 张图，只追加。因此自动继承"版本不可变、期固定 `persona_version`"，
   不新增表。
2. 默认穿搭不是一条记录：`brief.outfit_id` 缺省/null 即现状（`refs` + `default_outfit`），
   老角色、老作品零迁移。
3. 每期选一套（`brief.outfit_id`），不做每场景/每镜换装。
4. 生成时选中穿搭的第 1 张图**替代** `persona.refs[0]`，参考图为 `[穿搭图, 地标图]`，
   **不**同时给基础图。
5. `outfit_override`（文字）保持"仅记录"，不进提示词；本决定不改变它。
6. 穿搭图删除只从最新版本移除，旧版本与已建作品照常引用，文件不删（PRD §3 参考图只追加）。

## 依据（GX10 实验，2026-10-12，`spike/outfit/`）

2 个角色 × 2 套穿搭 × 3 个地标，Qwen-Image 2.1，同一种子，对比：

- C 现状 `[基础, 地标]`：基线。
- A `[穿搭, 地标]`：12/12 单人、穿搭正确、脸与基础图基本一致、地标保留。
- B `[穿搭, 基础, 地标]`：12/12 画成两个人（模型把基础图当成第二个人）。

所以 B 不可用，也就不需要给 `services/inference` 接三参考图工作流。

## 已知局限

- 实验的穿搭图由模型从基础图改出，"脸一致"偏乐观；用户上传的真实穿搭照的脸漂风险未测，
  待 GX10 端到端时用真实素材复核（PRD 一致性目标 ≥ 90%）。
- A 的人物姿态偏僵（棚拍站姿被带进画面），个别结果有背景纹理噪点。实验用的是固定提示词
  “站在…前”，生产的 `kf_prompt` 由脚本 LLM 按镜头写动作与机位，是否同样发生未验证；
  在 GX10 端到端用真实 `kf_prompt` 复核后再决定是否调提示词或工作流，不预先改。
- 脚本 LLM 不知道穿搭，可能写出与服装矛盾的动作；不在本期处理。
- 不做：每镜换装、按文字生成穿搭图、官方角色穿搭。
