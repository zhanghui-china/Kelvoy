# 0007 · 任务结果事务与目录版本快照

- **Date**: 2026-09-27
- **Status**: Accepted in part; execution-isolated publication remains open
- **Builds on**: [0004](0004-local-sqlite-no-cloud-infra.md)

## Context

逐镜生成时，用户可以同时选择另一镜。若 Worker 把开始时读到的整期文档写回，行版本冲突会把一次成功的模型运行误算成生成失败；若强制覆盖，又会丢失用户选择。失败任务、镜头状态与积分退款分开提交也留下崩溃窗口。角色和目的地版本号若不对应不可变文档，则历史期无法重现。

## Decision

- 任务领取时得到带期限的租约令牌。结果、失败终态、积分结算和领域状态由 `packages/store` 在同一个 SQLite 事务内提交；令牌不匹配或期限已过时拒绝提交。数据库写冲突与模型失败分别处理，不能消耗同一重试预算。
- 逐镜结果只合并该任务负责的镜头字段，保留其他镜的审核操作；同镜输入在生成期间改变时拒绝过时结果，并留下可重试的失败状态。
- 目的地更新保存不可变版本，期的读取与生成按 `destination_version` 取对应文档。旧数据库缺失的历史版本无法恢复；迁移只冻结当前文档作为近似值，表内标记 `compatibility_approximation`，审片台提示使用者。
- 历史目录回填有持久迁移标记，只在旧数据库首次升级时运行。

## Remaining work

租约令牌目前约束数据库提交，但 HTTP 推理、ComfyUI 任务、ffmpeg 和文件发布尚未由统一取消信号和执行专属产物目录贯通。不能据此宣称旧 Worker 已停止耗 GPU 或产物绝不会被并发执行覆盖。下一批须完成取消、期限、不可变发布与崩溃注入。
