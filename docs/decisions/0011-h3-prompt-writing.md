# ADR-0011：官方 H3 提示词编写由 Worker 承担

状态：已采纳（2026-10-10）

每次 H3 视频生成（首次、人工编辑后生成、失败重试）都需要按固定官方指南编写英文最终提示词。编辑框中的 `kf_prompt`、`motion_prompt`、`beat` 保留原稿，不能用模型改写结果覆盖。

## 职责与数据流

Engine 从期与镜头构造纯数据上下文：景别、机位、动作 beat、画面与运动描述、场景、按实际上传顺序排列的参考图角色、画幅、实际生成时长。实际时长为 `max(4, min(5, ceil(shot.duration_s)))`，剪辑目标不变。Engine 调用注入的编写接口，只有成功结果才可传入 video provider；缺少编写能力或编写失败必须失败，不能降级提交原稿。

Worker 读取随版本发布的 `skills/h3-prompt-writing`，完成参考文件读取与散列、StepFun HTTP 调用、超时、取消、结构化输出校验和缓存。沿用 `STEPFUN_API_BASE` / `STEPFUN_MODEL` / `STEPFUN_API_KEY`。LLM 单次上限 60 秒；格式校验失败最多纠正一次。输入与输出均经过 Engine 已有内容审核。Inference 只接收已编写的最终 prompt，将其传给 H3，不进行二次改写。

I2VA 读取 base-en 指南，按官方首帧指令与三段格式组装；Ref2VA 读取 base-en 共享规则及 ref-en 指南，按六段格式组装。实际读取的指南文本均计入 skill 内容版本。英文描述保持原动作、构图和机位，一个连续镜头；参考标记对应真实文件顺序。字幕不作为模型输入，禁止新增对白或可读画面文字，`non_diegetic_music` 为 `N/A`，配乐仍由后期合成提供。不调用视觉模型，不把未提供的图像细节描述成已观察到的事实。

## 存储与故障

有效结果原子发布至期内 `h3-prompts/<input_hash>.json`。输入散列包含上下文字段、实际参考图内容散列、模式、时长、画幅、官方文档内容版本、编写器版本及模型配置；不包含租约或重试标识。同一期相同输入可跨任务与租约复用，修改字段、替换参考图或更新版本会重新编写。缓存命中仍重新执行内容与格式校验，并返回同一来源记录。

`model.video.prompt` 是实际提交 H3 的全文，可选 `h3_prompt` 来源记录包含 skill 内容版本、编写器版本、模型、输入散列、模式、时长和按上传顺序排列的参考图散列。提交视频前再次核对参考图散列，防止编写期间文件变化造成提示词与参考依据错配。旧记录缺少字段仍有效。视频素材缓存已有最终 prompt 作为输入散列的一部分；不批量重生成历史视频。独立提示词缓存不影响旧素材保留策略。

失败沿用队列重试、任务失败与积分释放；内容拦截直接进入现有终态处理。取消不发布未校验结果。提示词编写计入原视频积分价格，无新动作、数据库迁移或 HTTP 路由。手工保存只保存字段，不执行编写或扣费。

## 发布与验收边界

官方提交固定为 `d21241f0a4b3acbb34c97dae47fa417b7065e438`，原文与参考文件不修改；来源、SHA256 与上游 README 所链接的许可来源保存在 `UPSTREAM.json`，同时分发 LICENSE / NOTICE。运行时不下载 GitHub 文件，不安装另外八种风格流程。

线上仅使用临时私有作品和模拟 LLM / Inference，证明格式、记录及调用链一致；不提交真实模型任务，不修改原黄山作品，不将模拟验收表述为真实出片画质验证。保留原 7 人运维白名单。
