# ADR-0014：失败镜头必须有重试入口

状态：已接受（2026-10-11）

## 背景

GX10 真实使用中，镜头失败后用户只能在页面最底部的进度区点一个"重试"，且一次只重试最近的一个失败任务；4 镜失败要点 4 次。"失败但找不到可重试任务"（历史失败没写任务记录、同镜已有活动任务、状态已 `retried` 但镜头仍 `failed`）时只显示文字，没有任何动作。

## 决策

1. `POST /api/episodes/:id/retry` 增加互斥的可选参数 `shot_no`、`all`；都不传时行为不变（`skills/kelvoy-vlog` 依赖）。
2. 镜头 `failed` 但没有可重试任务记录时，服务端按镜头状态补发新任务：`references` 作品入 `video`；`keyframe` 作品已有有效 `kf_selected` 入 `video`，否则入 `keyframe`。补发走与普通重试相同的积分预留，新任务被视为一次新的生成。
3. `all` 在单个事务内处理当前阶段下的全部失败镜头：先合计价格、一次校验余额，不足则整体 `insufficient_credits`，不留半截任务或预留。不在当前阶段的失败列入 `skipped`。
4. 详情响应新增 `failed_tasks`；`failed_task` 保留。
5. 前端：失败镜头卡片上直接提供"重试这一镜"，进度区在失败数 ≥2 时提供"重试全部失败镜头"，删除"没有可重试任务"的死胡同文案。

## 不变

- 状态机不改（`failed → rejected` 仍非法），失败镜头的"标记重生成"保持禁用。
- 自动重试上限（`MAX_LOCAL_ATTEMPTS = 2`）与 H3 校验不动。
- 被内容审核拦截的失败也提供按钮；"先改这一镜描述"的引导留待后续。

## 影响与风险

- 同一"阶段+镜头"的更早失败记录在重试时一并置为 `retried`，避免旧失败被再次当成可重试项。
- `all` 要求同镜只入队一个任务：同一镜同时有 `keyframe` 与 `video` 失败时只入最近的一个，另一个在 `skipped` 里说明。
- 补发的积分按新任务计；余额不足时 `all` 一个都不重试，用户可先单镜重试。
- 无数据库迁移；Web 与 Worker 需同版本发布。回退即切回上一发布目录，已入队任务按原逻辑被旧版本消费。
