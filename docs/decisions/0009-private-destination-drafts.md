# 0009 · 私有目的地草稿与共享发布

- Date: 2026-10-08
- Status: Accepted
- 依据：用户要求创建目的地、按地标上传照片、无需管理员审核直接共享，并保留旧期冻结版本。

## 决定

沿用 Destination、landmark refs 与 destination_versions，不增加生成流水线。草稿单独进入 SQLite destination_drafts，永不混入公共目录；creator_id 标识共享条目的创建者，官方条目缺省／null。编辑公开条目先创建私有草稿，发布在 immediate 事务内校验编辑版本及公共基准版本，写入完整目录和不可变版本快照。相同草稿版本重复发布返回同一发布记录。

协议校验及发布完整性属于 engine；SQLite 的所有读写、归属和乐观锁属于 store；web 负责会话、请求大小、照片格式、文件命名与路径检查、失败文件清理。三个模块既有边界不变。仅创建者可读取和修改草稿；公开和通用目的地图片接口以已发布版本引用为授权依据，保留历史引用支持旧期。

不从文件目录推导公共资源，不接受客户端加入任意照片引用。文件写入不能与 SQLite 原子提交：上传先写服务端命名的文件，事务追加引用失败则清理本次文件。请求并发由 edit_version 及 immediate 事务控制。进程被强制终止时可能留下无引用文件，但未发布引用的文件不能经公共接口读取。历史照片禁止在用户移除／删除草稿时物理删除，避免旧期失效。

## 上线和回退

上线前对线上 SQLite 和 projects 素材做一致性备份，在数据库副本上重复 open 验证迁移幂等，并执行 quick_check。新表使用 create table if not exists；旧官方记录不改写、已有历史快照不覆盖。回退代码保留新表和新文件即可，不清空用户上传；恢复旧数据库会丢失上线后的变更，必须先停止服务并保全新数据。

验收使用两个隔离账号核对发布前不可读、发布后跨账号可选和建期，以及编辑后旧期仍读取原版本。验收不触发 GPU 生成。

## 图片校验依赖

已有 Bun／Node 内置 API、Hono 及现有 workspace 无 JPEG、PNG、WebP 的完整解码器。仅检查容器头能放过压缩数据损坏的图片，不足以保障后续参考图可用。Web server 增加 sharp（libvips）依赖，用真实解码校验，拒绝告警／损坏数据，限制输入为 1 亿像素以约束解压规模。不改写原图，不引入模型／AI 识图。官方安装文档明确支持 Bun、macOS ARM64 和 Linux ARM64：[sharp 安装](https://sharp.pixelplumbing.com/install/)。部署必须在目标平台按 lockfile 安装 optional 原生包，不复制 macOS 二进制到 GX10。
