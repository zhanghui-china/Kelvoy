# PR07 推理适配审计与验证

基线 `fa76a86`，保留 StepFun、ComfyUI 双参考直出、传统关键帧路线和横竖画幅。本轮不新增模型、不接入 `/llm` / `/upscale`，不改积分和模型/工作流参数；仅双参考视频请求预算调整为 270 秒，取消清理另限 10 秒。

## 已有能力（源码核对）

- `packages/engine/src/stages/script.ts` 调用 StepFun，支持首次脚本、重生成和指令优化；规则校验与纠错已存在。
- `local-image.ts` / `local-video.ts` 负责请求映射，Worker `generation/local.ts` 校验参考路径、参考哈希、产物目录、单产物和种子，并保存模型、工作流哈希、时长与缓存元数据。
- Python `/image/` 接单/双参考生图；`/video/` 按一张关键帧或两张角色/场景参考分流。两条视频路线支持 9:16、16:9。
- ComfyUI 图链接检查、媒体流式下载与校验、HTTP 断连取消、Worker 执行令牌与产物隔离已有回归，不因本次审计重写。

## 本轮可复现缺口与修复

1. ComfyUI 返回合法 JSON 的数组、null 或错误嵌套类型时，原适配器的 `.get()` 可抛出未捕获 `AttributeError`，绕过定向取消；空数组历史还被误认为任务未完成。先用本地 mock HTTP 复现，再增加对象、字符串和媒体列表的边界校验，错误走既有 502 与定向取消路径。
2. Worker 原把任意 2xx JSON 强转成功响应，JSON 语法错误还被记为 network。先复现 9 个失败用例，再将畸形成功响应归类 `invalid_response`，检查必需字段与有限非负耗时。路径/任务身份仍由归档层校验。

本地协议回归使用 mock HTTP，不调用 GPU；不能替代真实模型质量、耗时或取消语义验收。最终测试命令与结果由本次提交交付记录提供。

## 历史真机证据的限制

`docs/audit/2026-09-27-code-audit.md` 记录四条 3.042 秒、24 fps 的原始视频片段：双参考横竖屏和关键帧横竖屏。`scripts/dgx-workflow-acceptance.py` 直接访问 ComfyUI；它绕过生产 FastAPI 包装端点与 Worker。双参考横屏 256.2 秒高于包装端点 240 秒预算，因此不得称为端点闭环通过。较早 smoke 文档仅是一镜技术样片，旧 30 镜成片迁移读取也不是新流程两期验收。

## 截止、取消与重试边界

- Python `generate()` 对图像/关键帧视频用 240 秒、双参考视频用 270 秒 `asyncio.wait_for` 覆盖上传到媒体校验；到期取消生成协程，已提交任务按 prompt ID 调用取消。取消清理单独使用 10 秒总期限，清理耗时可使实际返回晚于生成预算。
- Worker `callInference()` 有 300 秒 HTTP 超时，执行令牌失权或关闭则主动 abort；Python 监测断连并取消对应协程。
- consumer 最多执行两次本地尝试；第二次失败进入终态并按既有事务退款。增加超时预算会延长 GPU 占用与用户等待，不能只改验收脚本掩盖生产失败。
- 本轮获准并落实：仅双参考视频生成预算 270 秒，同时独立限制取消清理最多 10 秒，保留 Worker 300 秒及其他生成 240 秒。默认预算、路由分流、挂起取消不遮蔽原错已做本地回归；256.2 秒单样本不足以承诺负载下稳定达标。
