# Kelvoy 旅行 Vlog 生产

通过现有 Kelvoy HTTP API 驱动生产。服务负责模型、队列、数据与合成；Agent 负责需求整理、操作和审核协作。

## 开始前

- 首版使用已核对的 GX10 `c8ab053` 部署契约；当前 main 的 compose_ready／固定一秒流程不在此范围，未知或新版实例先暂停并核对。先读 [API 与版本说明](references/kelvoy-api.md)，核对用户提供的服务地址、可用会话及目标版本能力。健康接口成功不能证明生成链路可用。
- 新建期需要实例中已有且可用的角色、目的地、模板；续跑需要作品 ID，返工还需要镜号和意图。按名称读取列表并解析实际 ID，多个匹配让用户选择，不臆造 ID。
- 缺资料时给出 `/personas`、`/destinations` 或 `/templates` 页面入口；角色三视图未确认时引导到角色编辑页。首版不创建素材，不确认三视图。
- 用户已明确指定的需求直接采用；仅追问缺项与歧义。提交前展示需求摘要，明确的“制作”指令已授权建期，无需重复确认。
- 默认逐镜模式、9:16、约 30 秒。镜数和时长按作品 `pacing_version` 与服务规则读取，不能把新规则写入旧期。

## 操作

生产或处理返工时读 [生产流程](references/production-workflow.md)，请求形状查 [API 参考](references/kelvoy-api.md)。

1. 读取环境、会话、素材和已有作品。首次调用确认支持版本；未知能力标记为未知，不试发生成请求探测。
2. 新建时调用建期接口并立即记录返回的 `episode_id`；续跑先查询指定作品，按当前状态继续，不重新创建。
3. 单次观察最多 60 秒，约每 5 秒查询一次，单个等待不超过 5 秒。仍在生成时报告当前阶段和作品 ID，保留恢复入口。
4. 在 `script_review` 展示分镜与地标引用，等待用户修改或通过决定；在 `kf_review` 展示候选与参考图，等待逐镜选择；在 `clip_review` 展示片段、切段位置和质量检查，等待审核决定。
5. 仅提交用户明确决定的审核操作。通用“全自动”“一直跑完”不替代三个审核点的决定。缺少预览能力时提供审片链接，不猜选图或自动批准。
6. 推进前检查全部必要镜头已选图或已审核，即使旧服务未强制校验也不能跳过。写入按顺序执行，每次使用最新 `row_version`。
7. 返工只提交指定镜头；先保存用户要求的 prompt，再提交重生成。失败镜头使用目标版本支持的手工重试，不混用两种接口。重新合成保留已审核镜头。
8. 到 `done` 后核对成片文件可访问，返回受保护的产物链接。只有用户要求分享时才开启分享。

## 异常与恢复

- 401 暂停并引导登录；404 区分对象缺失和接口不支持；501 说明能力未实现。不直改 SQLite、不调用内部推理或 ComfyUI 绕过服务。
- 409 重新读取状态与版本，对比用户决定的对象。决定仍适用且状态未变化才重新提交；候选、镜序或阶段变化时重新展示给用户。
- 写请求断网或超时后先查询结果，不能盲目重发建期、继续、重生成、重试或合成。结果不明时保留“待核对”，不要叠加任务。
- Worker 管理自动重试。耗尽后展示失败原因，等待用户明确手工重试决定，不自建重试循环。
- 缺配乐时说明原因；仅在用户选择无配乐且版本支持时保存该选择。素材不足则报告差额，不自行缩短镜头或改变目标。
- 恢复记录只需服务地址、作品 ID、最后观察状态及未执行的用户决定；凭据留在受保护会话中，运行产物不写进技能目录或 Git。

## 反馈与交付

每次反馈说明作品 ID、阶段、已完成内容、待决定事项、审片入口。区分“已提交”“生成中”“待审核”“成片可访问”，不能凭任务入队或历史验收宣称本次完成。

交付包含成片链接（标明需登录）、实际验证过的时长／尺寸／帧率、AI 标识检查结果及可读取的模型成本。没有测量或字段缺失时说明未知，不把预期参数或估价当成实测。分享链接仅在用户要求且已开启时提供。

请求示例：

- “用已有阿澄、黄山和名山登顶模板做一期安静的旅行 Vlog。”
- “继续作品 e_demo，告诉我目前需要审核什么。”
- “作品 e_demo 第 3 镜动作太大，改成缓慢转身后重生成视频，其他镜头保留。”
- “作品 e_demo 重新合成，保留所有已审核镜头。”
