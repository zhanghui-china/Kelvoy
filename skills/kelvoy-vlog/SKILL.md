# Kelvoy 旅行 Vlog 生产

通过 Kelvoy HTTP API 驱动生产。服务负责模型、队列、数据、积分与合成；Agent 负责整理需求、执行操作、协助三个人工审核点。

## 开始前

- 需要用户提供服务地址和可用会话。先读 [API 参考](references/kelvoy-api.md) 的会话与积分两节。`GET /api/me` 验证会话并读余额；响应没有 `balance` 说明不是当前 main 契约，停止并告知用户。
- 新建期需要实例里已有的角色、目的地、模板；续跑需要作品 ID；返工还需要镜号和意图。按名称读列表并解析 ID，多个匹配让用户选。缺资料时给出 `/personas`、`/destinations`、`/templates` 页面入口，本技能不创建素材。
- 用户已明确的需求直接采用，只追问缺项。提交前展示摘要和 `credit_quote`；明确的"制作"指令已授权建期。余额不足先告知，不建期。

## 操作

流程见 [生产流程](references/production-workflow.md)，请求细节查 [API 参考](references/kelvoy-api.md)。

1. 读环境、会话、素材、已有作品。
2. 新建期后立即记录 `episode_id`；续跑先读作品，按当前状态继续，不重新创建。
3. 单次观察最多 60 秒，约每 5 秒查一次。仍在生成就报告阶段和作品 ID，保留恢复入口。
4. 三个审核点：`script_review` 展示分镜和地标；`kf_review` 展示候选（仅 `keyframe` 模式，默认的 `references` 模式没有这一步）；`clip_review` 展示片段、切点、检查项。每个审核点等用户的决定。
5. 只提交用户明确做出的决定。"全自动"、"一直跑完"不代替审核决定；没有预览能力就给审片链接，不猜选图、不自动批准。
6. 推进前检查必要镜头都已选图或审核。写入按顺序，每次使用最新 `row_version`。
7. 返工只动指定镜头。已有成品要改用 `/regen`，失败的任务用 `/retry`，坏镜用 `/report-bad`。`clip_review`／`done` 阶段不能改 prompt，见流程文档。
8. 到 `done` 后读 `episode.final`、核对成片可访问，返回受保护链接。用户要求才开分享。

## 红线

- 审核决定只能由用户做。
- 写请求超时或断网后先查结果，不盲目重发建期、继续、重生成、重试、合成。结果不明就标"待核对"，不叠加任务。
- 不直改 SQLite，不调内部推理或 ComfyUI，不用 PATCH 改状态绕过校验。
- 遇到 402 停下告知，不自己发积分、不换账号。
- 凭据留在受保护会话里，产物和恢复记录不写进技能目录或 Git。

## 异常与反馈

- 401 引导登录；404 区分对象缺失与接口不存在；409 重新读状态，决定仍适用且对象未变才重提，镜序、候选或阶段变了就重新给用户看。其余错误码见 API 参考末表。
- Worker 管理自动重试。耗尽后展示失败原因（`failed_task`），等用户决定再 `/retry`，不自建重试循环。
- 每次反馈说明作品 ID、阶段、已完成内容、待决定事项、审片入口。区分"已提交"、"生成中"、"待审核"、"成片可访问"，不能凭任务入队宣称完成。
- 交付含成片链接（标明需登录）、时长／尺寸／帧率（实测还是服务记录要分清）、AI 标识检查结果、积分与模型成本。缺字段就说未知。

请求示例：

- "用已有阿澄、黄山和名山登顶模板做一期安静的旅行 Vlog。"
- "继续作品 e_demo，告诉我目前需要审核什么。"
- "作品 e_demo 第 3 镜视频有问题，重做，其他镜头保留。"
- "作品 e_demo 重新合成，保留所有已审核镜头。"
