# ComfyUI Bridge 在 Spark 上的一镜技术测试（2026-09-25）

## 范围与限制

这次测试只验证新提交的 Qwen-Image 2.1 双参考图与 MiniMax-H3 首帧生视频工作流能否在 `spark-c327` 调用；不是 M0 正式的角色一致性或地标保真评审。输入是 ComfyUI 中现成的虚构角色测试图和 `lingshan.jpg` 网图，尚无团队的正式角色图或三地实拍参考图。

固定输入：角色图 `2026-09-10__frieren_peach_con_free5__fern.png`，地标图 `lingshan.jpg`，seed `20260925`。生图使用双参考工作流、9:16、1.0 MP。视频使用生成的关键帧作首帧、5 秒、6 步、MiniMax-H3 FL2VA + v1.2 4-step Turbo LoRA；分别测试最短边 480 与 704。工作流运行前队列为空。

## 新工作流的兼容性问题

1. `2_0_Image2Video_MinimaxH3_api.json` 原带 `GetNode`/`SetNode`，当前 ComfyUI `/object_info` 不提供这些节点；原图还借助 `Anything Everywhere` 隐式注入 `clip`/`model`，Prompt API 提交时因必填输入缺失返回 400。隔离分支中的 API JSON 改为显式连线，测试先红后绿，ComfyUI 提交校验通过。
2. 工作流中的 `SolAttnMiniMax` 在 480 测试采样开始时触发原生 `Fatal Python error: Aborted`，终端堆栈指向 `sol_attn_minimax_v2.py:302`，启动脚本自动重启 ComfyUI。移除这一加速补丁、保持其余模型与参数后，相同 480 输入成功生成。当前只能认定该组合在这台节点上不稳定，尚未定位第三方节点内部的具体缺陷。
3. 新桥接服务依赖 Flask，但 Spark 的默认 Python 环境没有 Flask。技术测试直接使用 ComfyUI HTTP API；产品接入将走既有 `services/inference`，见 ADR-0006。
4. 图像输出宽高受工作流 32 像素对齐约束，为 768×1376，略偏离数学上的精确 9:16；视频为 480×864。最终 1080×1920 需在产物处理环节验证缩放/裁切，不能仅检查表单参数。
